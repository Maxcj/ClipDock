# ClipDock 1.2.1

ClipDock 1.2.1 聚焦剪贴板历史的可靠性、隐私和大文件体验。重复复制会把已有内容重新置顶，高频复制更不容易漏记，图片预览更稳，链接元数据请求也变得更克制、更可控。

### 本次更新

- 复制已有内容时更新使用时间并回到列表顶部，不再生成重复记录
- 重构剪贴板捕获链路，拆分监听、捕获、分类、去重、存储、清理和图片处理职责
- 高频复制时使用待处理变化队列，避免上一轮处理未结束导致新内容被跳过
- 剪贴板记录、文件缓存、链接元数据和清理任务改用后台 Core Data context，减少界面卡顿风险
- 图片文件预览使用 ImageIO 生成受限尺寸缩略图，并让预览弹窗第一次点击即可居中打开
- 链接元数据默认阻止本地和私有网络请求，并增加全局 3 并发限制

ClipDock 1.2.1 focuses on clipboard history reliability, privacy, and large-file handling. Recopying existing content now promotes it to the top, rapid copy bursts are handled more reliably, image previews are safer, and link metadata requests are more controlled.

### What’s New

- Recopying existing content updates its usage time and moves it back to the top instead of creating duplicates
- Refactored the clipboard pipeline into clearer monitoring, capture, classification, deduplication, storage, cleanup, and image responsibilities
- Rapid copy bursts now use a pending-change queue so new clipboard content is not skipped while the previous capture is still processing
- Clipboard records, file caching, link metadata, and cleanup now use a background Core Data context to reduce UI stutter risk
- Image file previews now use ImageIO for bounded thumbnails, and the preview window opens centered on the first click
- Link metadata blocks local and private network requests by default and uses a global 3-request concurrency limit
