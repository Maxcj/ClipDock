# ClipDock 1.2.1-beta2

ClipDock 1.2.1-beta2 继续加固剪贴板捕获链路。高频复制时会排队处理最新变化，数据库写入转到后台 context，链接元数据请求也增加了隐私保护和全局并发限制。

### 本次更新

- 剪贴板监听改为待处理变化队列，连续复制时不再因为上一轮处理未结束而漏掉新内容
- 剪贴板记录、文件缓存、链接元数据和清理任务改用后台 Core Data context，减少对界面的影响
- 默认阻止为 localhost、.local、.internal 和私有 IP 地址请求链接元数据
- 链接标题和 favicon 抓取增加全局 3 并发限制，避免批量链接造成网络和 CPU 峰值
- 继续拆分剪贴板存储相关职责，让 repository、链接元数据、文件缓存和通知声明边界更清晰

ClipDock 1.2.1-beta2 continues to harden the clipboard capture pipeline. Rapid copy bursts now queue the latest change, database writes move through a background context, and link metadata requests gain privacy protection plus a global concurrency limit.

### What’s New

- Clipboard monitoring now uses a pending-change queue so rapid copies are not missed while the previous capture is still processing
- Clipboard records, file caching, link metadata, and cleanup work now use a background Core Data context to reduce UI impact
- Link metadata requests are blocked by default for localhost, .local, .internal, and private IP addresses
- Website title and favicon fetching now has a global 3-request concurrency limit to avoid spikes during link-heavy histories
- Clipboard storage responsibilities are split further, keeping the repository, link metadata, file cache, and notification declarations cleaner
